Aide et guide BPMN 2.0

Prenez l’atelier en main et apprenez à choisir les éléments qui donnent du sens à vos processus.

Mis à jour le 14 octobre 2026

Les bonnes pièces, au bon endroit.

Un guide des éléments disponibles dans la palette, le menu ⋮ et la clé de changement de type de Flowkenstein. Les variantes proposées dépendent de la forme sélectionnée et de son contexte.

Le modèle décrit le fonctionnement métier. Flowkenstein dessine les processus ; il ne lance ni scripts, ni services, ni automatisations.

Prendre l’atelier en main · mode d’emploi

1. Organisez les acteurs

Le tableau démarre avec des couloirs. Double-cliquez sur un nom pour le modifier. « + Couloir » ajoute un acteur ; les hauteurs sont harmonisées et les fonds alternent pour faciliter la lecture.

2. Ajoutez les étapes

Choisissez une forme dans la palette horizontale, puis placez-la sur le tableau. Le bouton ⋮ donne accès aux autres éléments BPMN. Double-cliquez sur une forme pour écrire son libellé.

3. Reliez les formes

Utilisez l’outil de connexion ou la flèche du menu d’une forme. Lors du déplacement, l’alignement automatique facilite les connexions droites, sans afficher de repères d’alignement.

Déplacer, zoomer et modifier

Utilisez l’outil main pour déplacer le tableau. La molette ou les boutons − et + changent le zoom. Les poignées permettent de redimensionner les tâches et les couloirs. Si le contenu sort de la vue, le bouton « Revenir au contenu » permet de le retrouver.

Sous-processus

Un sous-processus réduit peut être ouvert pour détailler son contenu. Le bouton « Retour au processus principal » revient au diagramme d’origine. Les couloirs ajoutés dans cette vue appartiennent au sous-processus ouvert.

Enregistrer et exporter

Le tableau se sauvegarde automatiquement dans ce navigateur. Pour conserver une copie indépendante, ouvrez le menu ☰ et choisissez « Enregistrer sous… » : le fichier BPMN garde les formes, connexions et dimensions. « Exporter l’image… » produit une image PNG ou SVG.

Ouvrir un fichier

Dans le menu, choisissez « Ouvrir », puis un fichier BPMN ou XML BPMN 2.0. Les fichiers trop volumineux, complexes ou contenant des extensions non prises en charge sont refusés. Pour un fichier issu d’un autre logiciel, essayez une exportation BPMN 2.0 standard.

Changer d’appareil ou d’adresse

La sauvegarde locale ne suit pas automatiquement entre navigateurs, appareils ou noms de domaine. Exportez le fichier BPMN depuis l’ancien tableau, puis ouvrez-le dans le nouveau.

Événements

Ce qui arrive au processus. Le contour indique le moment ; le symbole intérieur indique le déclencheur.

Début

Un cercle simple marque le déclenchement. Utilisez-le pour montrer comment une nouvelle instance commence.

Exemple : Demande reçue.

Intermédiaire : réception / émission

Un double cercle représente un événement en cours de parcours. Réception : attendre quelque chose. Émission : produire un événement. Le marqueur plein distingue généralement une émission.

Exemple : Attendre une réponse ou envoyer une notification.

Fin simple

Un contour épais termine le chemin courant. D’autres chemins actifs du même processus peuvent continuer.

Exemple : Dossier clôturé.

Événement de bordure

Placez un événement sur le bord d’une activité pour réagir pendant qu’elle est active. Contour continu : l’activité est interrompue. Contour pointillé : un chemin supplémentaire démarre sans l’arrêter.

Exemple : Après 48 h, interrompre la validation ou envoyer une relance.

Fin de terminaison

Le disque plein arrête tous les chemins actifs de la portée courante. À l’intérieur d’un sous-processus, il termine cette portée, pas automatiquement tout le processus parent.

Exemple : Arrêter toutes les branches d’un dossier abandonné.

Les déclencheurs disponibles

Le même symbole peut exister à plusieurs endroits. Toutes les combinaisons ne sont pas valides : la clé de l’éditeur filtre les choix. Un début d’erreur, d’escalade ou de compensation appartient à un sous-processus événementiel, pas au début ordinaire d’un processus.

Tâches

Une tâche décrit un travail à réaliser. Choisissez un verbe et un objet : « Vérifier la demande ».

Tâche générique

À utiliser quand le mode de réalisation n’a pas besoin d’être détaillé.

Exemple : Analyser la demande.

Tâche utilisateur

Travail humain réalisé avec une application.

Exemple : Un conseiller approuve un dossier dans un écran.

Tâche manuelle

Travail humain effectué sans être piloté par une application de workflow.

Exemple : Contrôler physiquement un colis.

Tâche de service

Action automatisée réalisée par un service ou un système.

Exemple : Interroger une API de contrôle.

Tâche de script

Traitement décrit comme un script exécuté par un environnement compatible. Le dessin seul ne l’exécute pas.

Exemple : Calculer un montant.

Tâche de règle métier

Évaluation d’une règle ou décision métier. Elle produit un résultat ; la passerelle choisit ensuite un chemin.

Exemple : Déterminer le niveau de risque.

Tâche d’envoi

Action dédiée à l’envoi d’un message à un autre participant.

Exemple : Envoyer une demande au fournisseur.

Tâche de réception

Attente d’un message destiné au processus.

Exemple : Recevoir l’accord du client.

Passerelles

Une passerelle organise les chemins. Elle ne réalise pas elle-même un travail.

Exclusive · XOR

Séparation : une seule sortie est choisie. Convergence : les chemins alternatifs sont réunis sans attendre les autres.

Exemple : Recevable ? Oui ou non.

Parallèle · AND

Séparation : toutes les sorties démarrent. Convergence : attendre un flux sur chaque entrée avant de poursuivre. Pas de conditions sur les branches.

Exemple : Vérifier l’identité et préparer le contrat, puis attendre les deux.

Inclusive · OR

Séparation : activer une ou plusieurs branches dont les conditions sont vraies. Convergence : synchroniser les branches qui doivent réellement arriver.

Exemple : Demander les justificatifs nécessaires selon le dossier.

Événementielle

Le premier événement reçu détermine la branche. Les sorties mènent à des événements de réception compatibles ou des tâches de réception, pas à des tests de données.

Exemple : Attendre l’accord du client ou l’expiration du délai.

Complexe

Réservée à une règle de coordination que XOR, AND ou OR ne décrivent pas simplement. Documentez explicitement la règle.

Exemple : Continuer après deux validations sur trois.

XOR = un chemin ; AND = tous ; OR = ceux dont les conditions sont vraies. Une convergence AND après un choix XOR peut bloquer le parcours : elle attendrait une branche jamais activée.

Couloirs et sous-processus

Les couloirs attribuent les responsabilités ; les sous-processus organisent le niveau de détail.

Couloir

Classe les activités par rôle, équipe ou système au sein d’un participant. Un flux de séquence peut traverser les couloirs du même participant.

Exemple : Service client, back-office, système.

Participant / pool

Représente une organisation ou un participant indépendant. Un pool vide masque ses étapes internes. Deux pools communiquent par messages.

Exemple : Votre entreprise et un fournisseur externe.

Sous-processus réduit

Regroupe plusieurs étapes derrière un symbole +. Ouvrez son contenu pour garder une vue d’ensemble lisible.

Exemple : Détailler « Contrôler le dossier » dans une vue dédiée.

Sous-processus développé

Affiche ses étapes à l’intérieur du cadre. Les flux internes restent dans cette portée.

Exemple : Montrer les trois contrôles d’une qualification.

Activité d’appel

Le contour épais indique l’appel d’une activité ou d’un processus réutilisable défini ailleurs, contrairement au sous-processus intégré.

Exemple : Réutiliser « Vérifier l’identité » dans plusieurs processus.

Sous-processus événementiel

Le cadre pointillé contient un traitement déclenché par son événement de début pendant que la portée englobante est active. Ne le reliez pas au flux normal par des flèches de séquence.

Exemple : Traiter une réclamation reçue pendant le dossier.

Sous-processus ad hoc

Le marqueur ~ indique un ensemble de travaux sans ordre entièrement imposé. Précisez ce qui permet de terminer l’ensemble.

Exemple : Rassembler les pièces disponibles dans un ordre souple.

Transaction

Le double cadre délimite une transaction BPMN avec un protocole de réussite et d’annulation. Ce n’est pas simplement une tâche financière ou une transaction SQL.

Exemple : Réserver plusieurs prestations avec compensation en cas d’annulation.

Connexions

La forme de la ligne indique la nature du lien. Une flèche métier n’est pas une annotation.

Flux de séquence

Flèche pleine : ordre des étapes dans un même processus. Elle traverse des couloirs, jamais la frontière entre deux pools.

Exemple : Analyser → décider → traiter.

Flux conditionnel

Une condition autorise cette sortie. Un petit losange marque le flux conditionnel sortant d’une activité ; les sorties d’une passerelle se lisent avec leurs conditions.

Exemple : Montant supérieur à 1 000 €.

Flux par défaut

La barre oblique marque la sortie utilisée si aucune autre condition ne s’applique. N’en définissez qu’une par activité ou passerelle concernée.

Exemple : Sinon : demander une vérification manuelle.

Flux de message

Ligne pointillée, cercle à l’origine et flèche ouverte : échange entre participants distincts. Ne l’utilisez pas entre deux couloirs d’un même pool.

Exemple : Transmettre une commande au fournisseur.

Association / association de données

Relie une note ou une donnée à un élément. Une association de données indique un usage ou une production de données, pas l’ordre d’exécution.

Exemple : Lier un formulaire à la tâche qui le consulte.

Données et annotations

Ces éléments apportent du contexte sans créer une nouvelle étape du processus.

Document / objet de données

Représente une information utilisée ou produite : fichier, formulaire ou données. Le marqueur collection représente un ensemble.

Exemple : Dossier client, justificatifs.

Stockage de données

Le cylindre représente des informations qui persistent au-delà d’une instance du processus.

Exemple : Base clients, archive des contrats.

Annotation de texte

Ajoute une explication reliée par une association. Elle ne modifie pas le comportement du parcours.

Exemple : Contrôle exigé uniquement pour les nouveaux clients.

Groupe

Le cadre en tirets et points rassemble visuellement des éléments, même de couloirs différents, sans contrôler les flux.

Exemple : Regrouper les étapes de conformité.

Marqueurs de répétition

Les marqueurs se placent sur une activité. Ils changent sa signification, pas seulement son apparence.

Boucle

Répète la même activité suivant une condition définie.

Exemple : Revoir le document jusqu’à validation.

Instances multiples parallèles

Trois traits verticaux : une instance par élément d’une collection, avec exécution parallèle.

Exemple : Vérifier tous les justificatifs indépendamment.

Instances multiples séquentielles

Trois traits horizontaux : traiter les éléments de la collection l’un après l’autre.

Exemple : Faire valider le document par chaque responsable à son tour.

Activité de compensation

Deux triangles vers la gauche : travail qui compense une activité déjà terminée. Il s’agit d’un traitement métier dédié, pas d’un retour automatique en arrière.

Exemple : Rembourser une réservation déjà payée.

Les outils de l’atelier

Sélection : déplacer et redimensionner. Main : déplacer la vue. Lasso : sélectionner plusieurs formes. Espace : ajouter ou retirer de la place. Connexion : relier les éléments ; le type de lien dépend des éléments reliés. Ces commandes ne sont pas des éléments BPMN.

Pour un diagramme lisible

  • Nommez les tâches avec un verbe et un objet, et les événements avec un résultat ou un fait.
  • Écrivez les conditions sur les branches : Oui / Non, montant, seuil ou règle métier.
  • Un début n’a pas de flux de séquence entrant ; une fin n’en a pas de sortant.
  • Commencez simple, puis détaillez les variantes réellement utiles. Les couleurs décorent le diagramme ; elles ne remplacent pas les marqueurs BPMN.
  • Les bordures interrompent ou ajoutent un traitement : pensez au chemin alternatif et à sa fin.

Dans l’éditeur : choisissez une forme, puis la clé pour changer son type. Pour une bordure, placez un événement sur une activité. La clé et les menus n’affichent que les options compatibles avec le contexte.
