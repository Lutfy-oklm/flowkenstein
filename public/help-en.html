Help and BPMN 2.0 guide

Get started in the workshop and learn to choose the elements that give your processes meaning.

Last updated: 14 October 2026

The right building blocks, in the right place.

A guide to the elements available in Flowkenstein’s palette, ⋮ menu and change-type wrench. Available variants depend on the selected shape and its context.

The model describes business behavior. Flowkenstein draws processes; it does not run scripts, services or automations.

Get started in the workshop · user guide

1. Organize participants

The canvas starts with lanes. Double-click a name to edit it. “+ Lane” adds a participant; consistent heights and alternating backgrounds make the diagram easier to read.

2. Add steps

Choose a shape from the top toolbar, then place it on the canvas. The ⋮ button provides more BPMN elements. Double-click a shape to edit its label.

3. Connect shapes

Use the connection tool or the arrow in a shape’s menu. Automatic alignment helps create straight connections when you move shapes, without showing alignment guides.

Pan, zoom and resize

Use the hand tool to pan the canvas. The mouse wheel or − and + buttons change the zoom. Handles resize tasks and lanes. When content moves out of view, “Back to content” brings it back.

Sub-processes

Open a collapsed sub-process to detail its content. “Back to the main process” returns to the original diagram. Lanes added in this view belong to the open sub-process.

Save and export

The canvas automatically saves in this browser. For an independent copy, open the ☰ menu and choose “Save as…”: the BPMN file preserves shapes, connections and dimensions. “Export image…” creates a PNG or SVG image.

Open a file

Choose “Open” in the menu, then select a BPMN or BPMN 2.0 XML file. Oversized or overly complex files and unsupported extensions are rejected. For files from other software, try a standard BPMN 2.0 export.

Switch language, device or address

The French and English canvases on the same website share the same local diagram. Switching language changes the interface without translating your own labels. Saves do not automatically transfer between browsers, devices or domains. Export the BPMN file from the old canvas, then open it in the new one.

Events

What happens to the process. The outline indicates its position; the inner symbol identifies the trigger.

Start

A thin circle marks the trigger. Use it to show how a new instance begins.

Example: Request received.

Intermediate: catch / throw

A double circle represents an event along the path. Catch: wait for something. Throw: emit an event. A filled marker generally indicates a throw event.

Example: Wait for a reply or send a notification.

None end

A thick outline ends the current path. Other active paths in the same process may continue.

Example: Case closed.

Boundary event

Attach an event to an activity boundary to react while it is active. Solid outline: interrupt the activity. Dashed outline: start an additional path without stopping it.

Example: After 48 hours, interrupt approval or send a reminder.

Terminate end

A filled disk stops every active path in the current scope. Inside a subprocess, it terminates that scope, not automatically the entire parent process.

Example: Stop all branches of an abandoned case.

Available triggers

A symbol can appear in several positions. Not every combination is valid: the editor’s wrench filters the choices. Error, escalation and compensation starts belong to event subprocesses, not ordinary process starts.

Tasks

A task describes work to do. Use a verb and an object: “Review the request”.

Generic task

Use when the way the work is performed does not need to be specified.

Example: Review the request.

User task

Human work performed with an application.

Example: An adviser approves a case in an application.

Manual task

Human work performed without being managed by a workflow application.

Example: Physically inspect a parcel.

Service task

Automated work performed by a service or system.

Example: Call a verification API.

Script task

Work described as a script run by a compatible environment. Drawing it does not execute it.

Example: Calculate an amount.

Business rule task

Evaluate a business rule or decision. It produces a result; a gateway then selects a path.

Example: Determine a risk level.

Send task

Work dedicated to sending a message to another participant.

Example: Send a request to a supplier.

Receive task

Wait for a message addressed to the process.

Example: Receive the customer’s approval.

Gateways

A gateway controls paths. It does not perform work itself.

Exclusive · XOR

Split: choose one outgoing path. Merge: bring alternative paths together without waiting for the others.

Example: Valid request? Yes or no.

Parallel · AND

Split: activate every outgoing path. Join: wait for a flow on every incoming branch. Branches do not use conditions.

Example: Check identity and prepare a contract, then wait for both.

Inclusive · OR

Split: activate one or more branches with true conditions. Join: synchronize the branches that actually need to arrive.

Example: Request the supporting documents needed for the case.

Event-based

The first event received selects the branch. Outgoing paths lead to compatible catching events or receive tasks, not data-condition tests.

Example: Wait for customer approval or a timeout.

Complex

For coordination that XOR, AND or OR cannot describe simply. Explicitly document the rule.

Example: Continue after two approvals out of three.

XOR = one path; AND = all; OR = those with true conditions. An AND join after an XOR split can block the flow by waiting for a branch that was never activated.

Swimlanes and subprocesses

Swimlanes assign responsibilities; subprocesses organize the level of detail.

Lane

Organize activities by role, team or system within a participant. A sequence flow may cross lanes within the same participant.

Example: Customer service, back office, system.

Participant / pool

Represent an organization or independent participant. An empty pool hides its internal steps. Separate pools communicate through messages.

Example: Your company and an external supplier.

Collapsed subprocess

Group steps behind a + marker. Open its contents while keeping the overall view readable.

Example: Detail “Check the case” in a dedicated view.

Expanded subprocess

Display its internal steps inside the frame. Internal flows stay within that scope.

Example: Show three checks within a qualification stage.

Call activity

A thick border indicates a call to a reusable activity or process defined elsewhere, unlike an embedded subprocess.

Example: Reuse “Verify identity” in several processes.

Event subprocess

A dashed frame contains handling triggered by its start event while the enclosing scope is active. Do not connect it to the normal path with sequence flows.

Example: Handle a complaint received while the case is active.

Ad hoc subprocess

The ~ marker indicates work without a fully prescribed order. Specify when the whole activity is complete.

Example: Collect available documents in a flexible order.

Transaction

A double border marks a BPMN transaction with success and cancellation handling. It is not simply a financial task or SQL transaction.

Example: Reserve several services with compensation on cancellation.

Connections

The line style identifies the kind of link. A business flow is not an annotation.

Sequence flow

Solid arrow: order of steps within one process. It may cross lanes, never the boundary between separate pools.

Example: Review → decide → handle.

Conditional flow

A condition allows this outgoing path. A small diamond marks a conditional flow from an activity; gateway outputs are interpreted through their conditions.

Example: Amount greater than €1,000.

Default flow

A slash marks the path taken when no other condition applies. Define only one default for the relevant activity or gateway.

Example: Otherwise: request a manual check.

Message flow

Dashed line, source circle and open arrow: communication between separate participants. Do not use it between lanes of the same pool.

Example: Send an order to a supplier.

Association / data association

Link a note or data to an element. A data association indicates data use or production, not execution order.

Example: Link a form to the task that reads it.

Data and annotations

These elements add context without creating another process step.

Document / data object

Represent information used or produced: a file, form or data. A collection marker represents a set.

Example: Customer case, supporting documents.

Data store

A cylinder represents information that persists beyond a process instance.

Example: Customer database, contract archive.

Text annotation

Add an explanation linked with an association. It does not change flow behavior.

Example: Check required only for new customers.

Group

A dash-dot frame visually groups elements, including across lanes, without controlling flows.

Example: Group compliance steps.

Repetition markers

Markers belong to an activity. They change its meaning, not just its appearance.

Loop

Repeat the same activity according to a defined condition.

Example: Revise the document until approved.

Parallel multi-instance

Three vertical bars: an instance for each item in a collection, running in parallel.

Example: Check all supporting documents independently.

Sequential multi-instance

Three horizontal bars: process collection items one after another.

Example: Have each manager approve the document in turn.

Compensation activity

Two left-pointing triangles: work that compensates a completed activity. It is dedicated business handling, not an automatic rewind.

Example: Refund a reservation already paid for.

Workshop tools

Selection: move and resize. Hand: pan the view. Lasso: select several shapes. Space: insert or remove space. Connect: link elements; the link type depends on the connected elements. These commands are not BPMN elements.

For a readable diagram

  • Name tasks with a verb and an object, and events with a result or occurrence.
  • Label branches with conditions: Yes / No, amount, threshold or business rule.
  • A start has no incoming sequence flow; an end has no outgoing sequence flow.
  • Start simple, then add variants that are useful. Colors decorate the diagram; they do not replace BPMN markers.
  • Boundary events interrupt work or add handling: consider the alternative path and its end.

In the editor: select a shape, then use the wrench to change its type. For a boundary event, place an event on an activity. The wrench and menus offer context-compatible options.
